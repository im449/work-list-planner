# Work List Planner

Веб-приложение для управления задачами и личными финансовыми целями.
Проект развивается на Python и FastAPI и используется для практического
изучения разработки программного обеспечения.

**Сайт:** https://work-list.ru

## Технологии

- **Backend:** Python, FastAPI
- **База данных:** SQLite
- **Frontend:** HTML, CSS, Vanilla JavaScript
- **Отчёты:** генерация PDF
- **Развёртывание:** VPS, systemd, скрипт деплоя и GitHub Actions

## Возможности

### Управление задачами

- Канбан-интерфейс для организации задач
- Создание и редактирование задач
- Изменение статуса и архивация задач
- Административная панель с авторизацией
- Формирование PDF-отчётов

### Демо-режим

- Возможность познакомиться с интерфейсом без входа в обычный аккаунт
- Изолированные временные демосессии, отделённые от рабочих пользовательских данных
- Автоматическое истечение и очистка демосессий
- Ограничение частоты создания демосессий

Демо предназначено для знакомства с приложением. Для работы с личными данными
используйте обычный аккаунт.

### Аккаунт и безопасность

- Смена пароля авторизованным пользователем через личный интерфейс
- Проверка текущего пароля перед изменением
- Минимальная длина нового пароля — 12 символов
- Инвалидация ранее выданных токенов после смены пароля
- Хранение паролей в виде хешей, а не открытого текста
- Очистка состояния демосессии при обычном входе и выходе, чтобы демотокен
  не подменял токен обычного аккаунта

### Двухфакторная аутентификация (2FA)

- Подключение двухфакторной защиты из интерфейса аккаунта с подтверждением текущего пароля
- Настройка приложения-аутентификатора по QR-коду или секрету
- Проверка одноразового шестизначного TOTP-кода при входе
- Одноразовые резервные коды для восстановления доступа при отсутствии приложения-аутентификатора
- Хранение TOTP-секрета в зашифрованном виде, резервных кодов — в виде хешей
- Инвалидация ранее выданных токенов после включения двухфакторной защиты

Для обычного входа начинайте с главной страницы https://work-list.ru/.
Если включена 2FA, введите актуальный шестизначный код из приложения-аутентификатора.
Резервные коды предназначены для восстановления доступа и являются одноразовыми.
Не публикуйте и не передавайте никому секрет 2FA или резервные коды.

Для работы 2FA необходимо задать переменную окружения `TOTP_ENCRYPTION_KEY`
с корректным ключом Fernet. Ключ должен храниться в секрете и оставаться
неизменным, пока в базе есть зашифрованные TOTP-секреты.

### Накопления и финансовые цели

- Создание и ведение нескольких целей накоплений
- Настройка целевой суммы и срока накопления
- Календарь накоплений с редактированием сумм по дням
- Сводка по накоплениям и прогрессу достижения целей
- Архивация целей с сохранением их данных

### Годовой бюджет

- Планирование доходов и расходов по месяцам выбранного года
- Указание суммы, даты, категории и статуса операции
- Создание ежемесячно повторяющихся доходов и расходов
- Автоматическое создание отдельных операций на каждый месяц до конца года
- Корректная обработка дат 29, 30 и 31 числа с учётом длины месяца и високосных лет
- Независимое редактирование каждой созданной операции
- Разделение данных бюджета между пользователями
- Категории доходов и расходов с возможностью добавления, переименования и удаления
- Запрет удаления категории, которая используется в платежах
- Автоматическое обновление категорий в существующих платежах при переименовании
- Фильтрация операций по месяцу, типу, категории, диапазону дат и обязательности расхода
- Отбор фактических и запланированных операций по статусу
- Различающиеся статусы и действия для доходов («Ожидается» / «Получен») и расходов («Запланирован» / «Оплачен»)
- Месячная сводка с суммами доходов, расходов, баланса и визуальным прогрессом оплаты
- Сводка по отфильтрованным операциям: количество, фактические доходы и расходы, баланс, ожидаемые доходы и запланированные расходы
- Проверка корректности диапазона дат перед отображением результатов

## Запуск для разработки

1. Клонируйте репозиторий и перейдите в каталог проекта.
2. Создайте виртуальное окружение:

   ```bash
   python3 -m venv .venv
   source .venv/bin/activate
   ```

3. Установите зависимости:

   ```bash
   pip install -r requirements.txt
   ```

4. Настройте необходимые переменные окружения, включая `SECRET_KEY` и
   `TOTP_ENCRYPTION_KEY` (ключ Fernet для шифрования секретов 2FA).
   Для локального запуска используйте отдельную тестовую базу данных, а не
   базу с данными рабочего приложения.

5. Запустите приложение:

   ```bash
   uvicorn main:app --host 127.0.0.1 --port 8000
   ```

## Тестирование

Запуск тестов из виртуального окружения:

    .venv/bin/pytest -q

Файл `conftest.py` настраивает отдельную временную базу SQLite для тестов.
Тесты API охватывают авторизацию, изоляцию данных пользователей, операции
годового бюджета и управление категориями, включая создание, переименование,
удаление и обработку повторяющихся названий.

Не запускайте автоматические тесты на базе данных рабочего приложения.
Предупреждения о deprecated-функциях не означают провал тестов, если все
тесты завершились успешно.

## Деплой

При push в ветку `main` GitHub Actions сначала запускает тесты, а затем
выполняет деплой по SSH, если тесты прошли успешно. На сервере скрипт
`deploy.sh` обновляет код командой `git pull --ff-only origin main`,
проверяет компиляцию Python, перезапускает systemd-сервис и проверяет
доступность приложения и основных страниц/API.

Для ручного деплоя на настроенном сервере:

```bash
./deploy.sh
```
